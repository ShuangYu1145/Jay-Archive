# 在线音乐

主导航新增「在线」，沿用杰作的 Miuix、COUI、Material 3 主题、卡片、顶栏、安全区、侧栏及玻璃导航。音乐 → 专辑保留原有资料、封面与飞行动效，点击任何曲目通过登录后的 QQ 音乐搜索并匹配歌曲。匹配要求歌名、歌手相符，优先同名专辑；多个不明确结果不会自动播放。

「在线」支持网易云和 QQ 音乐独立账号、二维码登录、昵称/头像/账号标识、搜索、自己的歌单及喜欢的歌曲。QQ 支持手机 QQ 与微信扫码，请使用弹层中所选的 App。二维码每两秒检查一次，取消本地三分钟强制失效；应用切到后台仍在 Activity 存活期间检查结果。关闭弹层、切页或进程重建不会取消服务器二维码或生成新码。二维码是否失效以平台返回为准，失效后由用户手动刷新。QQ 私密自建歌单通过带会话的本人歌单接口读取，收藏他人的歌单走公开详情；网易云喜欢歌单校验创建者。歌曲列表支持分页，播放歌单时先补齐后续页面再建立队列，单次最多 10,000 首。

## 配置服务

在「在线 → 音乐服务」输入两个自己信任的 HTTPS API 地址：

- 网易云：`@neteasecloudmusicapienhanced/api` 4.41.1 的根地址。
- QQ：`@yakult-green-tea/qq-music-api` 3.3.6 的根地址。

兼容 Folia 使用的这两类后端协议；没有复制 Folia 的界面或源代码。参考 [Folia](https://github.com/chthollyphile/folia-major)、[网易云 API](https://github.com/neteasecloudmusicapienhanced/api-enhanced)、[QQ API 文档](https://github.com/yakult-green-tea/qq-music-api/blob/main/docs/README.md)。

服务地址未配置时不请求公共代理；修改地址会清除该平台登录态。账号 Cookie/会话令牌通过 Android Keystore 的 AES-GCM 加密保存，并排除云备份和设备迁移。网易云 Cookie 放在 POST 正文，QQ token 放在 `X-QQ-Session`，不会放到 URL。服务请求不跟随重定向；服务根地址仅接受 HTTPS。退出登录立即清除设备凭据并停止该账号的播放。

## 保存二维码与切回登录

扫码弹层提供「保存二维码」与「刷新二维码」。保存的是原始二维码图片转成的 PNG，保留清晰像素并添加白色留白，写入系统相册 `Pictures/杰作`。Android 10 及以上使用 MediaStore，无需读取相册权限；Android 8–9 在首次保存时请求写入存储权限。保存失败会提示，不会留下未完成的媒体条目。

可先保存，再切到 QQ／微信／网易云的相册扫码入口识别。应用进入后台时不再取消服务器登录二维码；Activity 存活期间继续检查扫码结果。返回、切换标签或重建进程时恢复同一二维码、对应扫码通道和状态，不会重新请求 key。二维码及待完成的确认结果通过 Android Keystore AES-GCM 加密保存，与平台、服务地址绑定，并排除备份。

收到授权成功后先保存确认结果，再获取用户资料；即使此时网络中断，重开应用也能继续完成账号连接。仅手动刷新、切换扫码通道、退出账号或修改服务地址会放弃旧二维码；应用不承诺延长音乐平台本身的二维码有效期。平台返回失效时保留当前画面并提示手动刷新，不会在用户切出扫码时静默换码。

本次 19 项在线音乐相关单测通过；Android 测试验证待扫码与已确认信息加密保存/恢复、真实 MediaStore PNG 写入与发布，以及后台生命周期继续检查、返回保留原 key、手动刷新更换 key。未使用真实个人账号授权，实际扫码结果仍以平台返回为准。

## 服务证书验证开关

「在线 → 音乐服务 → 验证服务证书」默认开启，设置自动保存，切换后对后续音乐 API 请求立即生效。开启时使用正常证书链和主机名校验，包括下述指定域名的证书信任配置。

关闭时仅对网易云、QQ 音乐 API 连接跳过证书链和主机名校验，可用于自签名证书或证书域名不匹配的调试服务。HTTPS 仍加密传输，但无法确认服务器身份，登录 Cookie/令牌可能被截获；界面会在关闭状态显示这一提示。该开关不修改全局 TLS 默认设置，也不影响图片、更新检查或实际音频 CDN 的证书验证。

同一份设备设置同时供前台请求和后台播放服务获取音源地址时读取，不会因为改变验证方式删除已保存的账号凭据。重新开启后恢复严格校验，无需重启应用；未校验的连接会在请求结束后关闭，不保留到连接池中。

本次验证：16 项在线音乐相关单测通过；Android 真实穿透测试确认同一个客户端在开启时拒绝证书不匹配的 IP，关闭时可以连接，再次开启后恢复拒绝，并确认全局 TLS 默认配置未改变。另验证设置默认开启并可跨存储实例恢复。 Miuix、COUI、Material 3 的独立开关交互测试共 3 项通过，覆盖开启状态、关闭提示及两次切换的自动保存。原有动态主题截图测试在本次模拟器测试时钟中停顿，已中止；本次新增开关使用独立主题测试完成验证。

## 樱花穿透自动 TLS

本次手机连接失败的穿透地址使用樱花穿透自动生成的自签名证书，证书只包含 `frp-oil.com`，不包含 `113.219.237.106`。浏览器手动忽略证书错误后可以打开页面，不代表 Android 应用也会信任该证书。

此隧道在 QQ 服务设置中应填写 `https://frp-oil.com:23745`，不能填写 IP。当前构建通过 Android Network Security Configuration，仅为 `frp-oil.com` 信任已核验的这张公开证书；其他域名继续只使用系统证书，仍禁止明文 HTTP，并保留正常的主机名校验。没有关闭全局 TLS 校验或安装系统级证书。

证书资源：`app/src/main/res/raw/sakura_frp_qq_2026.pem`。SHA-256 指纹为 `28:28:62:ED:99:6F:95:3B:55:0B:5D:6F:12:6D:92:E7:EF:9E:5B:40:0C:BF:02:0F:1A:71:C7:FF:42:C4:A3:30`，当前有效期至 2027-11-08。若重建隧道、更换证书或证书到期，需核验并更新此证书资源，或改用系统信任的有效域名证书。

真实网络探针已确认：指定证书与域名后可以获得穿透 API 的二维码 key、二维码图片，且穿透健康接口的实例身份与本地 QQ 服务相同。 Android 37 模拟器也已使用应用原生 `HttpsMusicApiTransport` 通过真实穿透获取并解码二维码，同时确认原 IP 地址仍因 TLS 校验失败而被拒绝；15 项在线音乐相关单测通过。`OnlineMusicTlsTest` 提供可选的 Android 实机网络测试，默认不会访问外部隧道；传入 `musicTlsProbe=true`、`musicTlsProbeBase`、`musicTlsProbeIpBase` 后验证真实二维码和 IP 访问应被拒绝。

## 自行部署

仓库提供 `services/music-api/`，包含固定版本 npm 依赖、Docker Compose 与 Caddy HTTPS 配置。需在自己的服务器上安装 Docker Compose，并将域名解析到服务器，放行 80/443。

```sh
cd services/music-api
cp .env.example .env
# 编辑 .env，填写 MUSIC_API_HOST，并将下面生成的随机密钥填入 QQ_SESSION_SECRET
openssl rand -hex 32
docker compose up -d --build
```

应用填写 `https://你的域名/netease` 与 `https://你的域名/qq`。保持 QQ 会话卷与密钥不变可跨容器重启保留服务端设备身份和加密会话。此配置在本次环境未实际部署；部署后先检查 `/qq/login/channels` 与 `/netease/login/qr/key` 返回 JSON，再用手机扫码验证账号。

## 播放

Media3 服务托管真实播放队列、后台音频与锁屏媒体控制。队列保留平台和歌曲身份，加载每首歌时通过该账号重新获取音源地址，因此后台切歌也不会依赖提前保存的过期 CDN URL。保持播放/暂停、进度、上一首/下一首、倍速、单曲循环、迷你播放条展开/下拉收起与歌词页。QQ Serverless 会话在刷新账号时尝试续期。

本地 FLAC 和提取封面已删除，专辑统一使用目录封面；不再导入或播放本地音频。在线封面与歌词跟随实际曲目更新。服务端未返回歌词时显示空态；试听音源不当作完整歌曲播放；版权、会员、地区及服务可用性以平台和当前账号的响应为准。
